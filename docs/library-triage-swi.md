# Library triage — SWI-Prolog

Which of SWI's bundled libraries load on Shumway today, and what each one that
does not needs. Generated by loading every `<swi>/library/*.pl` with
`use_module(library(X))` under the `swi` dialect (ADR-040) and recording the
outcome. Re-run with the opt-in `Shumway.Tests.DialectInterop` project
(`Swi_Triage_Sweep`, `SHUMWAY_SWI_LIB=<dir>`; optional `SHUMWAY_TRIAGE_OUT=<file>`).

**Snapshot: 79 of 128 load cleanly** (was 71; +8 this pass).

> **Methodology note (important):** a library that fails to load does **not**
> throw — `ExecuteUseModuleDirective` catches it and prints
> `warning: use_module(library(X)) failed: <msg>` to `Console.Error`, then
> `use_module` returns null and the enclosing `ConsultString` succeeds. The sweep
> therefore captures `Console.Error` per library and treats any `failed:` warning
> as a failure. (An earlier hand count that only watched for a thrown exception
> reported a spurious 128/128 — every library "loaded" because none threw.)

Note: "loads cleanly" = `use_module` produced no warning. It does **not** prove
full function — an undefined predicate only errors when *called*, and C/thread-
backend libraries load their `.pl` layer while their native part is separate.

## Fixed (the shim pass — with_mutex / queues / must_be / print_message / module_property)

Single-threaded compat surface added to the prelude + a C# builtin:

- **`with_mutex/2`** (= `once/1`) and `mutex_create`/`lock`/`unlock`/`destroy`
  no-ops — Shumway is single-threaded.
- **Message queues as FIFO buffers** backed by dynamic facts:
  `message_queue_create/1,2`, `thread_send_message/2,3`, `thread_get_message/2`
  (fails on empty — no blocking), `thread_peek_message/2`,
  `message_queue_destroy/1`.
- **`must_be/2`**, **`print_message/2`** (silent no-op / best-effort user_error),
  **`module_property/2`** (C# builtin: `exports/1`, `class/1`), **`string/1`**.

## Remaining blockers — ranked by libraries unblocked

### 1. `:/2` "Clauses not contiguous" — **~15 libraries (BIGGEST WIN)**

The single largest cluster: 15 libraries fail with
`Clauses for :/2 are not contiguous`. These use module-qualified clause heads or
`Module:Goal` in positions our consult pipeline collapses to a `:/2` predicate
definition, tripping the discontiguity check. Libraries: `apply_macros`, `debug`,
`make`, `optparse`, `prolog_stack`, `record`, `thread_pool`, `main`,
`persistency`, `predicate_options`, `prolog_clause`, `prolog_colour`,
`prolog_source`, `prolog_xref`, `thread`. Fixing how module-qualified
(`:/2`-headed) clauses are handled — or exempting `:/2` from the contiguity
check — unblocks the whole batch. **Next lever to pull.**

### 2. Missing internal predicates — ~15 libraries

SWI-internal predicates referenced (and, for the directive forms, called) at load:

| predicate | libs | note |
|---|---|---|
| `$clausable/1` | error, macros, ordsets, prolog_pack, qsave | "can this pred have clauses" — stub against dynamic/builtin status |
| `current_arithmetic_function/1` | arithmetic, check_installation, listing, settings | query the arith-function table; declared as a no-op directive but here *called* |
| `current_type/3` | csv, git, prolog_codewalk | library(error)'s type registry |
| `prolog_unlisten/2` | prolog_breakpoints, prolog_coverage | broadcast/2 unlisten |
| `lambda_like/1` | sandbox | yall introspection |

Each is a small Prolog/C# shim; `$clausable/1` + `current_arithmetic_function/1`
together cover 9.

### 3. Parse errors — the long tail (~18 libraries)

Distinct reader gaps, most structural:

- **SWI dicts `{...}` / `_{...}`** — `Expected … got LBrace '{'` / `got Atom '.'`
  (dict field access `X.field`): `threadutil`, `strings`, `dicts`, `zip`,
  `statistics`, `solution_sequences`, `shell`. A language feature (own arc), defer.
- **`X as Y`** tabling/option syntax (`got Atom 'as'`): `rwlocks`, `prolog_trace`.
- **Bare operator atom as operand** (`Operator atom cannot be the right operand of
  '='/'\=='  without parentheses`): `prolog_metainference`, `shlib`. SWI reads a
  bare operator atom as an operand in more positions than our reader.
- **misc one-offs**: `check`/`prolog_autoload` (`got Atom 'undef'`),
  `operators` (`operator_stack`), `hashtable` (`got LParen`), `pprint`/`prolog_deps`
  (`got Atom '.'`), `url` (`0'` quote), `prolog_profile` (`got Atom '.'`).

## Libraries with a C / thread backend — analyse by hand

These load their `.pl` layer where it parses, but their real function is native.
A decision per library on how much to reimplement in the C# SWI shim:

- **Threads** — now partly shimmed (`with_mutex` = `once`, message queues as FIFO
  dynamic facts). Remaining thread machinery (`thread_create`, thread pools, real
  concurrency): `thread`, `thread_pool`, `threadutil`, `rwlocks`. Out of scope
  without a Shumway thread model.
- **Foreign C** (front a C extension): `shlib`, `readutil`, `qsave`, `qpforeign`,
  `prolog_stack`, `prolog_pack`, `prolog_colour`, `check_installation`, `zip`,
  `dde`, `win_menu`. The C# layer would reimplement the useful part, or out of scope.

## Suggested order of attack (by impact)

1. **`:/2` module-qualified-clause / discontiguity fix** → ~15 libraries.
2. **`$clausable/1` + `current_arithmetic_function/1` (called form)** → ~9.
3. **`current_type/3`, `prolog_unlisten/2`, `lambda_like/1`** → ~6.
4. **Bare-operator-atom-as-operand reader relaxation** → 2 + likely others.
5. Structural arcs on their own: SWI dicts, `as` tabling options, real C/thread
   backends (per the user's by-hand analysis).
