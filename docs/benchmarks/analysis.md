# Van Roy baseline — analysis & hotspots

_Companion to [`baseline.md`](baseline.md), which is auto-regenerated by the
harness and only holds numbers. This file is hand-curated; the harness does
not touch it._

## Current state (2026-07-21)

Two tiers, both measured, both competitive:

- **Tier-0 (interpreter)** sits at ~7.5× of native-compiled GProlog and
  ~2.3× of SWI (geomeans) — down from ~13.6× / ~3.0× in June, the Phases
  28–33 arc measured (per-benchmark 1.4–5.2×, geomean ≈ 2.2×; table below).
- **Tier-1 (persisted region IL — the shipped `--with-compiled-il` shape)**
  wins over Tier-0 on every benchmark, 1.9–5.5×, geomean ≈ 3.3×, putting it
  at roughly **1–4× of native GProlog** by shape — and it beats SWI on the
  recursion/backtracking benchmarks.

### Tier-1 (persisted region IL) vs Tier-0

The harness's **Shumway T1** row: each benchmark compiled + linked with
`IncludeCompiledIl` (the linker's default **region** layout — what
`shumway-link --with-compiled-il` bakes into a bundle or `--exe`; runtime
promotion cannot produce regions), loaded via `LoadBundle` and timed warm
in-process, symmetric with the T0 cell. Interleaved min-of-5, equal `N/10`
warmup on both tiers:

| Benchmark | T0 µs/iter | T1 µs/iter | T1 speed-up |
|---|---:|---:|---:|
| tak | 36046 | 6550 | **5.5×** |
| nreverse | 63.8 | 13.5 | **4.7×** |
| crypt | 4918 | 1089 | **4.5×** |
| sendmore | 626778 | 168289 | 3.7× |
| queens | 648 | 197 | 3.3× |
| qsort | 124.2 | 41.8 | 3.0× |
| flatten | 48.7 | 17.0 | 2.9× |
| boyer | 13.2 | 4.7 | 2.8× |
| serialize | 70.3 | 28.7 | 2.5× |
| zebra | 5767 | 3121 | 1.9× |

(The 2026-07-21 fused-cons/struct round then improved the cons/struct-heavy
T1 cells further: serialize 28.7→22.3, nreverse 13.5→12.3, flatten
17.0→15.2, qsort 41.8→36.4 — see *Closed since June* below.)

**Measurement artifact, resolved (recorded because it cost a day).** The
harness's first T1 cells reported qsort at ~1.0× (no win) and one run showed
boyer T1 "4.5× slower" — both false. Each T1 measurement loads the persisted
assembly into a fresh engine, and **.NET's own tiered JIT re-compiles the
region method mid-measurement** when the warmup is too small (`bench(1)`);
with a loaded machine the medians landed on the un-tiered runs (stddev
50–90 % on those cells). Fix shipped: the T1 warmup runs `bench(N/10)` so
.NET tiering settles before the stopwatch starts. Lesson (again): a
low-stddev cell inside a noisy run is not trustworthy; interleaved min-of-N
is the discipline.

## Closed since June — no headroom left in these

The June 2026 edition of this file listed four "improvement targets". **All
four are done** — do not plan work against them:

1. **Inline arithmetic in Tier-1 IL** — shipped (ADR-018 both tiers, Phase
   28's try/catch-free IL fast lanes, Phase 33 fusions). The
   arithmetic-heavy trio shows the biggest T1 wins (tak 5.5×, crypt 4.5×,
   queens 3.3×).
2. **`=..` specialisation** — shipped: `Univ` builds the list directly in
   the heap with a single allocation; the "AST↔heap round-trip" June
   criticized no longer exists. Boyer runs 2.8× faster at T1.
3. **Heap-cell allocation fast-path** — shipped via the fused-cons round
   (2026-07-21). June's premise was wrong twice over: `AllocateHeap*` were
   already `AggressiveInlining`, and there is no per-allocation GC barrier
   (the heap GC runs at safe points). The real cost was the
   `get_list; unify_*; unify_*` window paying three call boundaries with the
   WRITE half in NoInlining slow paths; the fused helpers do the whole cons
   in one call with one two-cell bump.
4. **Unification specialisation** — shipped for the hot shapes, same round:
   `GetListVarXVarX`/`GetListValXVarX` + `GetStruct2VarXVarX`/
   `GetStruct2ValXValX` (arity-2 structures), emitted by an
   IlPredicateCompiler peephole; off-shape cases (attvars, PSTR, bound
   non-list, register growth) delegate to the generic sequence verbatim.
   serialize T1 28.7→22.3 µs (−22 %).

## Remaining headroom — the honest list

- **Fused-window coverage**: the peephole covers X-register windows and
  arity-2 structures. Y-register variants, wider arities, and read-mode
  `unify_value` chains are unfused — extend **only when a real program
  shows the pattern hot** (the Van Roy set no longer justifies more).
- **serialize** is still the worst T1-vs-native ratio (~3–4× after the
  fused round): GProlog's native compile of alloc+tree-walk is simply
  excellent. Remaining gap is dispatch/call constant, not a known missing
  optimization.
- **zebra** has the weakest T1 win (1.9×): its choice points are *real* (no
  cut to elide) — CP save/restore in IL is inherent to the search; ADR-026
  already measured variable-width CPs at a ≤1 % ceiling. Little headroom
  short of smarter indexing.
- **Wholesale native parity** would require a machine-code backend — out of
  scope, unchanged conclusion since June.
- **Harness hardening**: the external engines' startup subtraction uses a
  single spawn and poisoned cells on a loaded machine (one flatten-GProlog
  cell read 0.45 µs/iter). Worth fixing if cross-engine tables are
  re-generated regularly.

## Methodology limits (unchanged)

- Wall-clock only; `bench(0)` startup subtraction bottoms out as `<noise>`
  for sub-millisecond externals (boyer/serialize on gprolog).
- No memory tracking (use `--alloc` for Shumway-internal A/Bs — deterministic
  cells/iter, immune to thermal noise).
- One machine, one snapshot; different CPUs shift the ratios.

## Reproducibility

Re-run with the same setup:

```
dotnet run -c Release --project tests/Shumway.Tests.Benchmarks/ -- --vanroy --runs 5
```

For quick spot-checks (drift from the baseline), `--runs 3` is enough
to wash out most noise and runs ~40% faster.
